# 带引用问答与 Agentic 验收

## 验收范围

使用 `rag-dev` 独立 PostgreSQL 库和 Elasticsearch 索引，从公开服务入口上传和发布 45 份合成 Markdown 文档。问答题集含 9 道开发题和 4 道留出题，每道题在同一份索引上用固定策略和 Agentic 各运行两次，交替执行策略顺序。检索沿用每路 50 候选、RRF `k=1`、30 条精排窗口、Top 5 和同章节邻块补证。生成用百炼 `qwen-plus`。每次请求有 16 秒、6 次外部模型调用和 4,000 个序列化证据字符的累计预算。

自动检查逐条验证摘录与实际模型证据的绑定、引用版本与行号、应用可见范围、政策生效区间和预算。状态、参考事实和原文金标覆盖单列。原文金标用文档键、SHA-256 和原文范围核对。独立离线评分使用实际生成最终答复的上下文，模型评分与确定性验收分别记录。

## RAGAS 与人工复核

使用 RAGAS `0.4.4` 和独立调用的 `qwen-plus` 评判模型，温度 0，Factual Correctness 使用 F1。两个指标各成功评分 31 条、跳过 21 条、失败 0 条。跳过记录均没有事实陈述，包括两类拒答、澄清、政策冲突，以及 A09 一次结构校验退出。Faithfulness 的 31 条评分均为 1.00。Factual Correctness 均值为固定策略 0.623、Agentic 0.592，分母分别为 15 和 16，逐题分数保留在 `ragas.json`。

人工核查 A01、A02、A05、A09、H02 和 H03 的实际引用、原文和参考答案。A02 的原文支持 18 牛·米，并明确记录缺少保持时间，评判模型四次给 0 分。H03 的原文和参考答案都明确为每 18 天，评判模型四次给 0 分。A05 的 15 个自然日和适用日经确定性检查通过，模型事实评分为 0.67。H02 的两条摘录覆盖两个事实，状态仍为部分有据，确定性状态检查记录为失败。A09 的部分有据结果随补检能否找到 Q4 波动。保留原始评分，质量验收同时使用逐题状态、原文覆盖和人工复核。

## 可复现命令

```sh
uv lock --check
uv run --locked --env-file .env python -m rag.dev test
uv run --locked --env-file .env python -m rag.dev benchmark --evidence --repeat 1
uv run --locked --env-file .env python -m rag.dev answer-eval --split development
uv run --locked --env-file .env python -m rag.dev answer-eval --split all --paired --repeat 2
answer_run=.rag/dev/answer-eval-20261117-105419-018675
uv run --group evaluation --locked --env-file .env python -m rag.answer_score \
  "$answer_run/answers.json" --jobs 4 --out "$answer_run/ragas.json"
```

49 项隔离回归通过。既有检索的 10 道证据题在四种模式下 40/40 通过。原 30 题和新增 19 题的 `k=1` 固定候选回放分别精确复现 180 条和 114 条历史融合排序。题集和回放方法见[检索验收](retrieval-results.md)。

真实 HTTP 回退演练在设有 `RAG_AGENTIC_ENABLED=0` 的独立 API 进程发送 `strategy=agentic` 请求，响应报告 `strategy=fixed`，仅执行一轮并成功引用已发布的 18 天检修周期。应用侧也可直接请求 `strategy=fixed`。故障替身覆盖超时、总体截止时间、伪造证据 ID 和摘录下标、文档注入、越权、生成期间撤权、删除和换版，以及第二轮生成时仅首轮用到的证据失效。 [接口、配置和发布文档回填](../../rag/README.md#answer-with-citations)
