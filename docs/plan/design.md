# 多租户 RAG 首期设计

## 首批交付

首批交付 Markdown/TXT 上传、异步入库、双路检索、引用和原件下载。应用通过 HTTP API 接入，验收通过 curl 或 Python 脚本执行。检索包含 pgvector 向量召回、ES 关键词召回、RRF 融合和可选精排。 [自研 PoC 实测](../other/poc-results.md#自研检索消融)

首批采用自研链路，在服务端执行文档 ACL。RAGFlow 用作检索效果基线。其私有数据集通过了跨租户探测，同租户 API Key 可通过移除请求白名单读取受限文档。 [RAGFlow 对照](../other/poc-results.md#ragflow-同题对照) · [选型依据](research.md)

## 服务和存储

| 组件 | 职责 |
| --- | --- |
| FastAPI | 认证、授权、上传、查询任务、检索和引用。 |
| PostgreSQL + pgvector | 保存租户、授权、原件、文档版本、切片、向量和后台任务。服务端以 PostgreSQL 中的发布版本和读取权限判定证据能否返回。 |
| Elasticsearch | 提供 BM25、短语和编号匹配。关键词索引可由 PostgreSQL 重建。 |
| Python Worker | 入库与 ES 同步分别运行，从 PostgreSQL 的 `jobs` 表各自领取 `ingest` 和 `sync` 任务。 |

首期使用 `rag-dev` Compose 项目，运行 PostgreSQL 和 Elasticsearch。从空库初始化八张业务表，通过上传接口导入验收样本。 [数据库设计](schema.md)

## 权限

- 应用凭据绑定应用和租户。服务端据此确定租户，再检查应用对目标知识库的权限。首批授权包含读取和写入，权限配置由运维命令管理。
- 文档默认沿用库的读取权限。需要收窄时，在文档上配置允许访问的应用名单。空名单拒绝读取。上传和任务查询检查库写权限，检索、引用和下载检查库读权限和文档名单。
- 业务表使用带租户键的外键和行级安全（RLS）。API 和 Worker 在事务内建立租户上下文。凭据查找和任务领取各自只需要少量调度元数据。
- 撤权和删除在 PostgreSQL 提交时生效。ES 的权限字段可能有延迟，服务从 PostgreSQL 复核每个候选的租户、知识库、当前版本和读取权限。授权存储不可用时，请求失败。

## 上传、发布和索引同步

1. **受理上传。** 校验应用的库写权限、文件类型和大小。PG 在一个事务里保存原件、待发布版本和入库任务，提交后返回 `202` 和任务 ID。相同幂等键和相同请求复用原任务，同键不同请求拒绝。
2. **处理版本。** 入库 Worker 短事务领取任务并设置租约，随后解析、切分和向量化。临时故障限次退避重试。进程崩溃后，租约到期的任务可重新领取。
3. **发布。** 块和向量齐全后，Worker 校验租约有效、待发布版本仍是最新目标、文档可用。在同一事务里更新文档的发布指针、完成入库任务并创建 ES 同步任务。新版本向量立即可查。发布前的解析或向量化失败时，旧版仍可查。
4. **同步 ES。** 同步 Worker 使用与发布共用的文档行锁，从 PG 读取当前发布版本和权限。按块 ID 写入 ES，并在同一租户、知识库和文档范围内清理旧变更的索引。写入、清理和刷新都完成后，确认对应变更序号已同步。旧任务处理时以当前发布状态为准。删除和 ACL 变更也在业务提交时写入同步任务。ES 故障独立重试，混合检索可回退到仍能完成授权复核的向量路。

任务查询分别返回入库阶段、当前发布版本、ES 同步状态和最近同步任务的尝试次数及错误。索引等待处理时为 `pending`，暂时失败时为 `retry`，达到重试上限时为 `failed`，可搜后为 `synced`。

默认留存 30 天。未删除文档从最后一个指向该版本的待发布或已发布指针切换时计时。已删除文档从删除时计时，并等待 ES 确认清理当前变更。仍有非终态入库任务的版本继续保留。运维命令按租户预览或分批删除 PostgreSQL 中的版本、原件和切片。文档删除标记、任务回执和上传幂等记录继续保留。 [清理命令](../../rag/README.md#apply-version-retention)

HTTP 响应通过 `X-Request-ID` 返回服务端生成的请求 ID。上传、库授权变更、文档读权限变更、发布、同步和删除写 JSON 日志。业务事件记录操作方、租户、资源 ID 和结果。入库和 ES 同步任务保存发起请求的 ID。CLI 命令生成自己的追踪 ID，物理清理按批次关联删除的版本。 [日志位置](../../rag/README.md#trace-requests-and-audit-changes)

## 检索与接口

查询先验证知识库范围，再并行请求 pgvector 和 ES。两路共用块 ID。候选在读取正文前经 PG 授权复核，随后可用 RRF 合并并执行精排。返回前复核证据有效性。证据提供文件、版本和原文位置。首批引用和下载面向当前已发布版本，打开时再次鉴权。

混合检索在一路召回不可用时，使用另一路并在 `degraded` 中标记故障分支。精排不可用时保留融合顺序。若选定的召回路径全部失败，或任一次 PostgreSQL 权限复核失败，请求返回 `503`。

业务服务使用阿里云百炼。入库和查询使用 `text-embedding-v4` 的 512 维向量，分别指定文档和查询输入类型。精排使用 `qwen3-rerank`。更换向量模型时重新生成已有文档的向量。

| 接口 | 首批行为 |
| --- | --- |
| `GET /v1/knowledge-bases/{code}` | 按调用应用所属租户和知识库读权限返回库的 ID、短码及名称。 |
| `POST /v1/knowledge-bases/{code}/documents` | 请求体为不超过 256 KiB 的 UTF-8 Markdown/TXT 原件，查询参数为 `filename`，请求头包含 `Idempotency-Key`。更新时传入 `document_id`。受理后返回 `202` 及文档、版本和任务 ID。 |
| `GET /v1/ingestion-jobs/{id}` | 查看入库阶段、重试、失败原因、发布版本和关键词同步状态。 |
| `PATCH /v1/documents/{id}/readers` | 需知识库写权限。`null` 继承库读权限，空数组拒绝读取，名单仅允许同租户应用。变更时提交 ES 同步任务。 |
| `DELETE /v1/documents/{id}` | 提交逻辑删除和 ES 同步任务。 |
| `POST /v1/retrieve` | 按 `knowledge_base_code` 和 `question` 查询。支持 `vector`、`keyword`、`rrf` 和 `rerank`，默认 `rrf`。 |
| `GET /v1/citations/{id}` | 按当前权限返回证据和原文位置。 |
| `GET /v1/documents/{id}/file` | 校验权限并下载当前发布版本的原件。 |

## 首批验收标准

| 场景 | 通过条件 |
| --- | --- |
| 上传到检索 | 两个租户各自上传一份同名 Markdown 或 TXT 文件。任务发布后向量路能命中本租户文档，ES 同步后关键词路也能命中。引用能定位原文，授权应用能下载对应原件。 |
| 租户与文档隔离 | 缺少库写权限的应用无法上传或查看任务。缺少库读权限或文档 ACL 的应用无法检索、打开引用或下载原件。跨租户请求和陈旧 ES 命中均无越权证据返回。 |
| 上传与版本重试 | 相同幂等键和请求返回同一任务与版本，同键不同请求被拒绝。Worker 中断后，任务可在租约到期后继续处理。新版失败时旧版仍可查，旧任务晚完成时无法覆盖已发布的新版。 |
| 故障与撤权 | ES 故障时混合检索返回经 PG 复核的向量结果并报告降级。ES 恢复后，同步任务使关键词路追上当前版本。PG 授权不可用时请求失败。撤权或删除提交后，检索、引用和下载均拒绝访问失效证据。 |
| 留存与审计 | 预览只报告候选数量。执行仅清理指定租户已过期的可清理版本及切片。当前版本、活跃任务和原幂等回执仍可用。通过响应 ID 可关联上传、发布和同步，以及文档读权限变更与删除。CLI 和清理操作可按事件追踪。 |
| 检索回归 | 使用相同 30 道题和原文金标复跑四种自研检索模式，提交 Recall@K、p95 和 PG 发布到 ES 可搜的时间差。生产指标门槛以业务语料和目标并发测试为准。 [PoC 题集](../../poc/questions.json) |

## 后续范围

首条链路验收后接入真实用户身份、文本型 PDF/DOCX、带引用问答及离线质量评测。用户委托调用的权限取应用授权与可信用户或组授权的交集。连接器、OCR、整库索引切换和多步检索按试点需求推进。
